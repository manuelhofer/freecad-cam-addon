Check on machine

Does the travel suffice? The panel works out, for every point of a CAM job's paths, where each axis of the machine has to be, and holds that against its limits – before the program goes to the machine.

How: open the document with the job (best select the job) – then click Check on machine in the toolbar. If no machine is open, the command opens it by itself: the one this job was last checked on, otherwise the one used last. The first time it asks for the file of your machine (Open machine …) or builds one (New machine …). With several machines open, it asks which one – the remembered one comes first. Only a saved machine is remembered. The panel opens in the machine's document so you can watch it move.

At the top: what is checked

  • Job – choose here if there are several.
  • Workpiece mount – only if the machine has several (two spindles, say).
  • Job origin – where the job origin sits on the machine, measured from the LCS of the workpiece mount along its axes – like G54 on the control. Empty fields use the suggestion shown in grey: the stock centred on the mount, its bottom on the clamping face. A bar from 4-axis machining sits in the chuck by its clamping length, exactly on its axis. The job remembers what you enter.

The result

Below the origin you find the verdicts, visible without scrolling – the details follow further down:

  • Axes – does the travel suffice?
  • Collision – before checking “Not checked yet – check now”: the link checks right away (like the button under “Collision”). Afterwards the verdict; where? scrolls to the “Collision” section.
  • Tool length – green if the measured gauge length is entered for every tool; otherwise yellow, naming the tools whose length was estimated – why? scrolls to the notes.
  • Cutting data – only if tool controllers of the job come from the tool manager: green if spindle speed and feed match it. Otherwise yellow, per controller, what the job has and what the tool manager calculates – after you changed vc there, say. apply sets that controller's spindle speed and feed, Apply all those of all of them – one undo step; the operations' step-over and step-down stay (“Cutting data into the job” sets those). The comparison uses the use case and material the addon last set the controller from, otherwise what “Cutting data into the job” suggests.

About the axes:

  • All axes stay within their limits. – green, all is well.
  • Otherwise one sentence per operation and axis, such as “X1 travels to 312.00 mm in “Pocket”; the limit is 250.00 mm (at X 450, Y 0, Z −5). At the limit the tip of T1 would be at X 388, Y 0, Z −5.” In brackets the point in the program; the second sentence says how far the tool tip gets – the axis itself is the slide, with a tool the tip is elsewhere. Click the sentence and the machine moves there – the axis stops at its limit, as far as it really gets. If the machine's X counts in diameter, X values are shown with “Ø” and doubled – as on the control.
  • In grey below, per axis, what the path needs and what the limits allow – so you also see how much room is left.
  • In grey the notes: which tool length was used, points the tool cannot reach at all (Y on a lathe without a Y axis, say), a missing turret station, commands the check does not know, a rotary axis in the program the machine does not have (A on a lathe with C, say – the check then ignores that rotation), a tool sitting across the path (CAM operations calculate their paths for a tool along Z; a radial turret station would run them across the part) – for All-round roughing the other way round: a tool that does not point radially at the axis from the direction the path is calculated for (from +X, say); two tools of the job in one station (see tool loading) – the machine would take only one. A note about a tool ends with Open T1 …: the tool manager opens at that tool. Once you save there (OK or Apply), the panel works with the new values right away – the measured gauge length or the chosen holder, say.

Close moves the machine back to where it stood when the panel opened and returns to the job's document.

Run through

The machine runs through the path as in the program: in the machine's 3D view the stock (translucent) and the part lie where the job's origin puts them, with the path on them – feed blue, rapid red; with a rotary axis it runs around the part and turns with it, as in FreeCAD. The tool sits in its mount: the cutting part yellow in its shape (the ball mill with a ball, the torus mill with a rounded corner …), the shank grey up to the overall length, above it the holder from the tool manager with its contour (see Holders); without one it is hinted at, translucent, if the gauge length is longer. Tool and workpiece move with the machine. None of this goes into the document; Close removes it again.

  • Operation – jumps to its start; while playing it shows where the path is.
  • The buttons: to the start, one point back, Play/Pause, one point on. On the right the Path tick: without it the path is off and you see better how the bar is removed – the addon remembers it. Next to it the magnifier: it brings workpiece and tool close in the view – the machine is usually much bigger than the part. Next to it the speed: ×1 is as fast as on the machine, ×100 a hundred times as fast.
  • The slider is the time within the job – drag it and the machine follows.
  • Below: the operation, the block running now (counted as in the operation's path, including the comments FreeCAD writes into it), the time so far and the whole time, then the position of every axis. If an axis cannot go further, it stops at its limit and shows in red at its limit.
  • Below that the tip in the program: where the tool tip is right now, in X, Y, Z as in the NC program, plus the rotary axes (“Tip in the program: X 16, Y 0, Z −28, C −3900”). The axes above are the slides – this is what the tool does. If an axis is at its stop, red text behind says where the tip should be (“– should be: X 100, Y 0, Z 18”).
  • Clicking an overrun also sets the player there – you can play on from that point.
  • Stock and finished part – for a 4-axis job with a round bar and “All-round roughing” or “All-round finishing”: the bar is removed while playing, just as the cutter moves – with its shape, the ball mill as a ball. At the last station the path disappears, the finished part turns grey, and the bar shows half transparent above it in colours, compared with the finished part and the allowance of the last operation (unchecked Part: the part disappears too and the bar is opaque): green the allowance, yellow a little more, red over 1 mm more (the cutter did not get there – after the ball mill, say, its rounding in an inside corner), blue into the part. Below it the sentence, such as “At the end 0.32 mm … 0.33 mm remain on the part (allowance 0.30 mm), nowhere into the part.” If all all-round operations have selected faces, only these get colours: what is not selected stays bar stock and does not count as “too much left” – blue (into the part) applies everywhere. Where the part does not lie all around the axis – say an end that stands beside the axis –, it does not compare and says from where to where: the bar knows only one radius per ray from the axis and would not see there what of the part remains behind the cutter. Going back recalculates from the start. A part in a block (stock from the model or with dimensions, the tools vertical from above – the mill) works the same way: the box is removed from above, every operation with the shape of its cutter (FreeCAD's own too), compared at the end with the top of the part – the colours as with the bar, with selected faces only on them. What lies under an overhang it does not see: 2.5D, from above.

The time: feed blocks with the feed from the path, without a feed at 1000 mm/min (a note says so); rapids per axis with the rapid traverse from the machine – the slowest axis sets the pace. Plus the acceleration of every axis from the machine (missing: 1 m/s² or 1 rev/s², the rapid 10 m/min – fixed, see Finding the acceleration): every block runs a trapezoidal profile – accelerate, travel, brake; before and after a rapid and at corners (direction change of 15° or more) the machine stops, through arcs and ramps it keeps going, a short block never reaches its speed. So every row costs its turn and every rapid its start. G93 (feed as the inverse of time – as “Rough all round” writes it) takes 1 ÷ F per block.

Collision

Does anything bump into something while running through? Check for collisions runs through the whole path and measures the distances at every spot:

  • the tool – cutting part, shank and holder – against the finished part (the job's model), against fixtures, table and everything on the machine that does not move with the tool. The cutting part touches the part in feed moves, that is intended – it must not touch it in rapid moves (a rapid move right after a feed move, up from a pocket floor, say, only counts once the cutting part gets closer to the part), and in feed moves it must not run more than 0.05 mm into the finished part: “… the cutting part of T1 runs into the finished part” means the tool would cut into the part there – when a radial tool runs a path calculated for one along Z, say. Deburring, engraving, threads and drilling may cut into the part: the model rarely shows their result;
  • the machine parts that carry the tool (spindle, head, slides, turret) against fixtures, table, chuck and the part;
  • what carries the workpiece against the fixed bed.

The stock does not count: the addon removes no material – what has not been cut yet is shown by the CAM simulator. Parts that already touch in the home position (a slide on its guide, say) are not checked.

  • Warning distance – if two bodies come closer than this, it shows in yellow (empty: 1 mm).
  • Then the verdict: green “Nothing touches …”, red “Something collides:”, yellow if something only comes close. One sentence per operation and pair, e.g. “In “Pocket”, the holder of T3 (“SK40 ER32”) and the part touch (block 12, at X 50, Y 30, Z −15).” – the worst spot, the first one if equal.
  • Click a sentence and the player goes there; a red ball marks the spot and the view centres on it.
  • It takes a few seconds depending on the path; meanwhile the button says Cancel. If job, origin or workpiece mount change, the result no longer applies and disappears.
  • A tool without holder is checked without one – a note says so.

How it calculates

  • It checks the paths in the job – the operations as the post processor reads them –, not a finished NC program.
  • Tool: the tip lies one tool length in front of the tool mount, against its Z axis. The length comes from the tool manager – the gauge length, otherwise estimated with the holder (holder length + overall length − clamping depth), without a holder the overall length –, otherwise from the CAM tool; a note says which.
  • Turret: tool T3 sits in station P3; the turret is indexed to its working position for it.
  • Rotary axes stand where the path says (A, B, C by their name in the program, C1 → C), otherwise at 0. The check works like a control without TCPM: X, Y and Z are the machine's axes – the linear axes stand as if the rotary axes were at 0, and the rotary axis turns the workpiece underneath. That is how FreeCAD shows the path, too. Endless axes have no limit.
  • Inclined axis: the path is rectangular; the check uses the real directions of the slides – the same numbers as moving “as in the program”.
  • The directions of the LCS matter: see Tool and workpiece mounts. If the Z axis of a tool mount points at the workpiece, a note says so.
