Write program

The addon's postprocessor turns a CAM job into the program for your control. It writes all active operations of the job in their order – the addon's and FreeCAD's own – and knows from the machine what a lathe needs differently. FreeCAD's postprocessors are built for milling machines; on a lathe with C axis and driven tools several things were missing there.

How to

  1. Select the job in the tree (or one of its operations), then Write program … in the CAM-Addon toolbar.
  2. Machine: choose the machine – any open one, even one not saved yet (“… – not saved”), and the remembered ones. Preselected is the one the job remembered when it was checked on the machine or in the 4-axis assistant; if it has none, the first open one. If the chosen one is in a file, the job remembers it. Below it says what the postprocessor knows: lathe or mill, X as diameter, the main spindle and its C axis (“main spindle S4, C axis C4”), which stations are driven (“T1…T12 → S1 (C1)”). Without a machine it writes as for a mill.
  3. Control: LinuxCNC, Siemens 840D, Fanuc, Haas or Mach3/Mach4. The job remembers the choice, so does the machine – for the next job on it, it is preselected.
  4. Settings on the left, preview on the right with the first blocks – you see every change right away.
  5. Save writes the whole program to the file (suggested: next to the document, with the control's extension – .ngc, .mpf, .nc, .tap).

The settings

They apply per control to all jobs and are preset so you need not change anything to get started. Every row has a sentence of explanation, every group a ? that jumps here. Bold is what you changed; yellow what the machine builder decides (with Fanuc the driven tool and the C axis – the program then contains a comment about it). Only what applies to the chosen machine is shown – on a mill no C axis and no driven tool. If a tick is off, the commands below it are grey: they are then not in the program. Reset brings the defaults back.

Placeholders in the commands: {t} tool number, {s} speed, {m} 3 or 4 (direction), {n} number of the drive, {h} number of the main spindle, {achsen} the axes of the change point; “|” separates lines.

Program

  • Comments – before each section the name of the operation and the tool (“; Rotary roughing T1”), at the start the name of the job. Off: blocks only – some controls dislike long comments.
  • Block numbers – N10, N20 … before each block, not before “%”, the program number and comments. They are not needed; some operators use them to jump in the program.
  • Program start, start on the lathe, program end – the fixed lines: units, plane (G18 on the lathe), at the end spindle and coolant off, M30.

Tool change

  • Tool change – on a mill “T1 M6”, on a lathe as the control wants it: Siemens “T1 D1”, Fanuc “T0101”, Haas “T101”.
  • Move to the change point – before each tool change and at the end, first alone the axis that pulls the tool away (X on a lathe, Z otherwise). You enter the point in “Edit machine” under “Home and tool change”, in machine coordinates (MCS) or from the job's origin (WCS). With Siemens “G0 SUPA D0 X… Z…” – SUPA switches off all offsets, D0 the tool offset; that is also how the Siemens manual does it (job planning 10/2015, p. 109, tool change routine). The field below offers two other ways:
    • F_HOME – on a machine with ShopTurn: the ShopTurn cycle that moves to the tool change point set there. A command without {achsen} appears once before each change and at the end. Whether F_HOME knows your point in a plain G-code program (without a ShopTurn program header), check in the control's simulation.
    • G75 {achsen} FP=1 – “approach fixed point”: the point from the machine data (MD30600); the values after the axes do not count.

Spindle and coolant

  • Spindle on and off – “M3 S…” (left M4), “M5”.
  • Driven tool – on a lathe M3 turns the part: a driven tool gets the command of its drive with the drive's number from the machine – Siemens “M1=3 S1=…” (drive S1), Haas “M133 P…”, LinuxCNC “M3 $1 S…”.
  • Coolant – as set at the operation: flood M8, mist M7, then M9. Off if you switch it by hand at the machine.

Main spindle and driven tools. A lathe with driven tools has two spindles, each with an S and a C: the main spindle turns the part (S) or positions it (C) – for milling it positions: “SPOS[4]=0”, then “C4=…” in the blocks. The tool drive turns the tool (“M1=3 S1=…”); its C axis only orients it and never appears in the path. Which spindle does what, the postprocessor tells from the machine: the spindle the tool stations hang on (“Driven by”) is the drive; the other one is the main spindle. The names are in “Edit machine”; “New machine …” asks for the numbers on the lathe.

C axis (lathe)

  • Switch the C axis on and off – before the first path with the rotary axis the main spindle switches from speed to positioning, at the end back, with its number: Siemens “SPOS[4]=0” / “SPCOF(4)” (main spindle S4), Haas “M154” / “M155”. Off if your machine does that itself.
  • The rotary axis in the blocks is the C axis of the main spindle – with Siemens its NC name from the machine, a number with “=” (“C4=90.000”); otherwise its letter.
  • X as diameter if the machine counts X that way (tick in “Edit machine”) – the paths compute the radius, the program shows twice that.

Feed

  • Feed 1 ÷ time (G93) – in paths where the rotary axis moves along, F is the time per block (1 ÷ minutes). So the feed at the tool is right however far it is from the axis. Then back to feed per minute: G94 on a mill, G98 on Fanuc and Haas lathes (there G94 is a facing cycle).
  • Without G93 (tick off) – for controls that cannot do G93: F in mm/min, computed so that each block takes as long as with G93. The distance counts from X, Y, Z and the rotary axis in degrees – that is how controls compute the feed when linear and rotary axes move together. Check that your control counts it the same way.

Swivel plane (3+2)

A swivelled plane is a job the addon swivels from a base job: the part stays clamped, the rotary axes turn it (or the head) until the tool stands perpendicular on an inclined face. When you write the base job, the operations of its planes follow in the same program – each plane swivelled once, back at the end.

  • With the control's swivel cycle (preset for Siemens) – before the plane's operations “CYCLE800(1,"",0,27,X0,Y0,Z0,A,B,C,0,0,0,-1,0,1)”: retract in Z, the swivel data set (between the quotes; empty if the machine has only one), new, axis by axis about Z, Y, X, the plane's origin in the base job, direction −1. Then the blocks are in plane coordinates; the control computes rotary axes and tool length itself, the zero point stays on the part. Back with “CYCLE800()”. Source: Siemens programming manual job planning 10/2015, pp. 678–681.
  • Without cycle (tick off, or the control has no command for it: LinuxCNC, Mach, Fanuc, Haas) – first to the change point, then “G0 A… C…”, the blocks with X, Y, Z computed for the rotated machine, afterwards the rotary axes to 0. Computed from the machine; without a machine only for an A table (about X) with rotary table C, the pivot at the base job's zero point.

Before the first run look at it in the control's simulation: whether the swivel data set, the direction and the retract suit the machine is decided by the machine builder.

Look-ahead and smoothing

Rotary paths consist of thousands of short blocks. Without look-ahead a control brakes at every block end – the machine jerks, the surface gets worse and it takes longer. Every control has commands for this; they go at the start of the program. Preset is what is usual for the control; what not every machine has is off and marked yellow – without the option the control stops with an alarm.

  • Siemens 840D – on: G64 (continuous-path mode), G642 (smoothing with tolerance), CTOL (the tolerance in the program instead of the machine data), SOFT (jerk-limited acceleration); off: COMPCAD (block compressor – often an option). Source: Siemens programming manual job planning 10/2015, pp. 470–471 (CTOL), plus the command list (G64, G642, SOFT, COMPCAD).
  • LinuxCNC – on: G64 P… Q…, corners rounded at most by the tolerance.
  • Mach3/Mach4 – on: G64 (constant velocity).
  • Fanuc – off: G08 P1 (look-ahead) and G05.1 Q1 (AI contour control), both options; not verified from a manual.
  • Haas – off: G187 P3 (smoothing fine); without the command, setting 191 of the machine applies.

Tolerance: how far the control may deviate from the programmed path when smoothing – preset 0.01 mm. Smaller is more accurate but slower.

Before the first run look at the program in your control's simulation: the commands for the C axis, the drive and smoothing follow the control's manuals; on the machine the builder decides some things differently.
